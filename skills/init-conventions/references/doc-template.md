# Convention doc template

Each file in `docs/conventions/` follows this shape. It is read by agents mid-task, so it must be short, imperative and scannable. Target 80 lines or fewer.

````markdown
# <Topic>

**Scope:** <where this applies: whole repo, a package, a language>
**Enforced by:** <linter/CI/hook name, or "review only">

## Rules

1. MUST <imperative, testable rule>.
2. MUST NOT <forbidden practice>.
3. SHOULD <default, with the exception condition stated>.

## Examples

<Include only for rules that are ambiguous without one.>

```<lang>
// Good
...
// Bad
...
```

## Legacy exceptions

<Only in repos with existing code that violates a rule. Paths or patterns exempt for now,
with the target state. Delete the section when empty.>

- `src/legacy/**`: uses <old pattern>; do not copy it into new code; migrate when touched.

## Rationale

<One or two lines per non-obvious rule. Skip when the rule explains itself.>
````

## Index (`docs/conventions/README.md`)

````markdown
# Conventions

Generated by `init-conventions`. Agents: read the docs that match your task (see the router in `AGENT.md`).

| Topic | Summary | Doc |
|---|---|---|
| Testing | <one-line summary of the key rules> | [testing.md](testing.md) |
````

## Writing rules

- Use RFC 2119 words (MUST, MUST NOT, SHOULD) so strength is explicit.
- One rule per line; no paragraphs of prose.
- Name the exact tool, flag, path or pattern; avoid "clean", "modern", "reasonable".
- State exceptions inside the rule they modify.
- Link to the owning doc instead of repeating a rule.
